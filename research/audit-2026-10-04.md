# A/B/C 전체 점검 — 2026-10-04

공통 데이터·검색/생성 코드·API 계약·계측·저장 결과를 점검했다. 재현한 비용 계산 오류를 수정했고 29개 테스트와 A/B/C의 새 실호출을 확인했다. 비교 그림은 원시 결과를 다시 검증한 뒤 [06_compare_results.ipynb](../notebook/06_compare_results.ipynb)에서 만들었다. 전체 평가 성능을 확인한 것은 아니다.

## 수정한 오류

| 재현 | 수정 | 확인 |
|---|---|---|
| Jev 응답의 `usage`가 문자열이면 `AttributeError` | 비정상/누락/음수 사용량을 불명확으로 처리, 정상 호출의 알려진 사용량은 보존 | malformed usage 테스트 |
| 생성 API 출력 토큰이 음수이면 음수 비용 생성 | 정확한 0 이상 정수 usage만 비용 계산, 불명확한 사용량·캐시 정보는 `None` | 음수/비정상 타입/캐시 정보 테스트 |
| NaN 가격이면 NaN 비용 생성, 음수 가격도 허용 | 유한한 0 이상 가격인지 유료 호출 전에 검증 | 잘못된 가격에서 실제 요청을 하지 않는 테스트 |

정상 usage를 가진 이전 파일럿의 비용은 이 오류의 영향을 받지 않았다. 모델·분류체계·탐색 정책을 바꾸지 않았다. cost helper의 코드 해시가 바뀌었으므로 기존 C 적재 2,000개 요청·완료 응답·동일 트리를 대조한 뒤 새 artifact에 provenance를 남겼다. 이전 artifact는 보존했고 다시 분류하기 위한 API 호출은 하지 않았다.

## 확인한 범위

- 2,000 / 10,000 / 40,000 공동 corpus의 해시·고유 ID·nested 포함 관계와 중복 passage의 동일 원문을 확인했다.
- 실제 보관 article에서 KILT100w passage를 재생성해 40,000개 원문 내용·제목·문단/문자 좌표를 모두 대조했다.
- 개발 200·평가 1,000문항의 원래 질문·정답/공동 근거 annotation 매핑을 대조했다. 질문 파일에는 정답과 근거 라벨이 없다. HotpotQA 공동 근거는 서로 다른 두 문서 이상을 요구한다.
- 원문 반환, 입력 잘림/예산 가드, A/B 후보 공유, C 복수 분기·재탐색·중복 제거·요청 한도·캐시/온라인 분리, 생성기·증분 저장을 기존 테스트와 함께 확인했다.
- 새 `load_comparison`은 해시·원문·실제 프롬프트·같은 A/B 후보·답변/근거 지표·응답 usage 비용·시간 합을 다시 확인한다. 잘못된 프롬프트/비용·중복/누락 결과를 거부하고 미측정 비용을 0으로 표시하지 않는다.
- `pytest -q`: **29 passed**. 04는 완료된 트리를 재사용했고, 05는 품질·실제 검색·전체 시스템을 끝까지 실행했다. 06은 API 호출 없이 실행하여 그래프·CSV를 내보냈다. 저장된 PNG와 HTML 렌더링을 확인했다. Jev Review는 공개 관련 소스만 보조 검토했고 코드·테스트·원시 결과로 판단했다.

37GB 전체 raw Wikipedia 파일을 다시 다운로드하거나 전부 재해시하지 않았다. 준비된 원문·QA를 대조한 범위와 공식 전체 KILT benchmark를 구분한다.

## 새 실제 시스템 런의 관측

원시 결과: [manifest](../results/20261004T012602_22979a7e/manifest.json), [system.jsonl](../results/20261004T012602_22979a7e/system.jsonl). 개발 NQ 1문항 + HotpotQA 1문항, 방법당 1회, 같은 2,000문단과 GPT-6 Luna다. 아래는 두 문항의 산술 평균이다.

| 관측 | A 기본 RAG | B 재정렬 RAG | C Jev 트리 |
|---|---:|---:|---:|
| 답변 EM / F1 | 0.50 / 0.50 | 0.50 / 0.50 | 0.50 / 0.50 |
| 공동 정답 근거 회수 | 2/2 | 2/2 | 2/2 |
| 실제 전체 응답, 초/질문 | 2.563 | 3.694 | 10.857 |
| 실제 검색, 초/질문 | 1.196 | 1.296 | 9.148 |
| GPT API 입력 토큰/질문 | 887.5 | 914.5 | 345.5 |
| Jev API 입력 토큰/질문 | 해당 없음 | 해당 없음 | 171,349.5 |
| Jev 호출/질문 | 해당 없음 | 해당 없음 | 23.5 |
| 최종 원문 수/질문 | 5.0 | 5.0 | 1.5 |
| 온라인 API 비용, USD/질문 | 0.0001005 | 0.0001032 | 0.0072430 |

세 방법 모두 HotpotQA는 `Focus`로 정답, NQ는 `I do not know`로 오답이었다. short-answer span 근거 회수 성공은 답변을 만들기에 충분한 사실 확보와 같지 않다. C는 두 문항 모두 재탐색 한도에서 중단했다. 확률 임계값에 의한 완결성은 정답 보장이 아니다.

A/B는 준비된 로컬 CUDA 모델, C는 원격 API다. 네트워크·journal 쓰기가 C 시간에 포함된다. 온라인 비용은 Jev 탐색 + GPT 생성 API 사용량의 가격표 기준 추정치이며 준비·로컬 GPU·사람의 작업 비용은 제외했다. Jev와 GPT 입력 토큰은 다른 tokenizer 계측이므로 합산하지 않는다. 현재 결과에서 C가 최종 GPT 입력은 줄였지만 전체 시간과 온라인 API 비용은 더 컸다. 두 문항만으로 일반적인 정확도·속도·비용 우위를 판단할 수 없다.

사전 준비는 A/B 공유 dense index 3.050초, C 트리 누적 80.548초와 API 비용 $0.081653082였다. 분류체계 작성·갱신 비용과 로컬 GPU 금전 비용은 미측정이다.

## 남은 검증

C 정책 보정과 고정, 미사용 평가 1,000문항, 10,000·40,000문단, 반복 지연 측정, 갱신·사람의 유지보수 비용은 아직 확인하지 않았다. corpus에는 정답 근거를 강제로 포함했으므로 축소 corpus 내 방법 비교로 해석하며 공식 전체 KILT 점수와 직접 비교하지 않는다. 이번 점검은 구현의 재현성과 작은 실호출 연결을 확인한 것으로, 연구 가설이 입증되었다는 뜻은 아니다.
